# Устройство Code Morphing Software 4.4.03 (что удалось установить)

Основа — разбор образа `cms4.4.03raptor.cru` своим дизассемблером (`docs/crusoe-isa.md`),
строки внутри образа, драйвер обновления из SP23689, документы Transmeta. Адреса — CMS-адреса
(смещение в образе + 0x8e000).

## Общая схема

    сброс → внутренний boot-ROM → Configuration ROM (93LC56B: PCI/DRAM)
          → поток из SROM-флеша → gunzip → RAM [TOM .. TOM+16 МБ) → вход в CMS
    CMS: интерпретатор x86 ─(горячий код)→ транслятор → кэш трансляций → исполнение
          │                                   │
          └─ эмуляция «системы»: CPUID, MSR, northbridge (PCI 00:00.x), SMM, LongRun

Три уровня исполнения x86 (Software Optimization Guide): первые проходы — интерпретация по
одной инструкции; после нескольких — трансляция в VLIW с кэшированием; редкие сложные
инструкции (`rep movs` малой длины, `cpuid`, `rdmsr/wrmsr`, `pusha`, `bsf/bsr`, `bts`,
`rdtsc`, `cmpxchg`, загрузка сегментов) уходят в «out-of-line» подпрограммы, которые не
планируются вместе с остальным кодом.

## Память

| CMS-адрес | что |
|---|---|
| `0x00000..0x8e000` | загрузчик CMS (не входит в образ) |
| `0x8e000..0x1823f0` | код (101 807 молекул, 1188 функций, вызываемых через `call`) |
| `0x1823f0..0x1b2261` | данные: таблицы диспетчеризации, CPUID, строки, DSA-ключ (~`0x182654`) |
| выше | BSS (`0x22edxx` — дескрипторы флеша, переменные), стек, куча, кэш трансляций |

С x86-стороны CMS-память занимает 16 МБ сверху: регистр северного моста `TOM` (00:00.0
`4Ah`, только чтение) показывает её начало. Размер **фиксирован**: ни BIOS, ни OCT его не
меняют (в BIOS Guide `TOM` RO). Из этих 16 МБ ещё 896 КБ отдаётся под SMRAM (T-сегмент).

## Как CMS обрабатывает CPUID (пример «декомпиляции»)

`f_a6798` (вывод `crusoe_dis.py … -c`, сокращено):

    cc = cmpil.c(eax, 0x80000006);  if (cc.nbe) goto L_a6860;   // 0x8086xxxx?
    cc = cmp.c(eax, 0x80000000);    if (cc.nb)  goto L_a68b8;   // 0x8000000x
    cc = cmpi.c(eax, 3);            if (cc.be)  goto L_a68b8;   // стандартные 0..3
    eax = ebx = ecx = edx = 0; return;                          // неизвестный лист
    L_a6860: if (eax > 0x80860007 || eax < 0x80860000) → нули
             f_12ade0();                                        // обновить LongRun-листы
             r36 = (eax - 0x80860000) * 16 + 0x18abc0 - 112     // запись из таблицы
    L_a68b8: eax = [r36]; ebx = [r36+4]; ecx = [r36+8]; edx = [r36+12];
    // стандартные листы: r36 = eax*16 + 0x18aaa0; 0x8000000x: (eax-0x80000000)*16 + 0x18aae0

То есть ответы CPUID — это **данные** в `0x18aaa0..0x18ac60`, их заполняет `f_a5e40` при старте
и переопределяют MSR `CPUID_TFMS / VND / MASK`. Для добавления «фич» правка таблицы бесполезна
без реализации самих инструкций — см. обсуждение SSE.

## Флеш CMS и OEM Configuration Table — протокол MSR

Восстановлен по драйверу `F1542_CMSDrv.sys` (SP23689) и подтверждён кодом CMS (`L_a69f0`,
`f_a6b10`):

| операция | что |
|---|---|
| `rdmsr 0x8086800N` (N = 1..5) | EDX = размер области N в dword |
| `wrmsr 0x80868000`, EAX = буфер, EDX = `0x8086800N` | CMS копирует область N в буфер (линейный адрес) |
| `rdmsr 0x80868000` | EAX = статус (0 = успех) |
| отдельная ветка `L_a6bf0` (старший полубайт EDX — команда) | запись; именно её зовёт SoftPatch |

Область 3 — **OEM Configuration Table (OCT)**: драйвер проверяет, что она начинается с
`OEM Conf Header`, а по `+0x1be` лежит `Transmeta(tm) Crusoe(tm) Processor`. BIOS Sony читает из
неё «OCT Version» (dword по `+0x428`). По BIOS Guide в OCT заданы `winxp_flags` (начальный
`PERF_CTRL`), `pci_arb_ctrl_initial_value`, `initial_pci_latency_timer`, SVID/SID, поля
`OEMOPT` (`reset value / canset / canclr`), init-циклы для загрузки с параллельного ROM, а
судя по строкам CMS — и уровни LongRun / делители памяти («CD configuration for level T%d»).
Таблицы МГц/мВ в самом образе CMS нет, что согласуется с этим: **рабочие точки — данные
платы в OCT, а не код CMS**.

Снять OCT и обе копии CMS на живой машине: `tools/cms_flash_read.py` (сначала `--sizes`,
только rdmsr). Проверяет ли CMS подпись при записи OCT — пока не установлено (следующий
шаг разбора — ветка `L_a6bf0` → `f_fd710`).

## Ограничения, о которых важно помнить

- CMS-память недоступна x86: всё, что выше, видно только через образ или через MSR-окна.
- Подпись DSA проверяется на образ CMS при штатном обновлении; изменить работающий CMS можно
  патчем в RAM (нужен доступ к CMS-памяти) или прошивкой SROM программатором.
- Recovery-копия + watchdog: испорченная основная копия не «кирпичит» машину.
