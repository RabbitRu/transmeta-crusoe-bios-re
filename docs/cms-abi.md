# Соглашение о вызовах (ABI) внутри CMS 4.4.03

Восстановлено статистически по всему коду CMS: 1188 функций, в которые входят через `call`,
и 5464 места вызова. Повторить: `python3 tools/cms_abi.py IMAGE`. Цель — чтобы новый код
(свой компилятор, патчи на ассемблере) мог вызывать функции CMS и вызываться из них.

Как считалось: для каждого атома известно, какие GPR он читает и пишет (`tools/cms_abi.py`,
`atom_rw`); молекула исполняется параллельно (все чтения раньше всех записей). Самый надёжный
признак класса регистра — со стороны вызывающего: **регистр записан до `call` и прочитан
после него без перезаписи** — значит, вызывающий рассчитывает, что вызов его не испортит.

## Классы регистров

| регистры | класс | доказательство |
|---|---|---|
| `%r0..%r10` | **состояние x86** (`r0..r3` = eax, ecx, edx, ebx — по статье; дальше, вероятно, esp, ebp, esi, edi, …) | вызывающие полагаются на них после вызова (r0: 406 раз, r1: 114, r2: 54); почти никто их не сохраняет (≤1 %): функции, которые их меняют, меняют x86-состояние намеренно (как CPUID) |
| `%r11..%r19`, `%r25..%r33` | **сохраняемые вызываемым** (callee-saved) | после вызова читаются: r11 451, r25 411, r12 288, r26 227, r13 169, r27 153 …; именно их функции пишут в кадр в прологе и восстанавливают перед возвратом |
| `%r20`, `%r21` | **глобальные указатели** (не трогать) | ~200 записей на весь CMS против постоянных чтений; служат базой: `ldi %r0, %r21, 50` (копии x86-MSR), `ldi …, %r20, -94` |
| `%r22..%r24` | особые, не выяснено | `%r24` сохраняется/восстанавливается вокруг захвата `f_b5ef0`/`f_b5df0` |
| `%r40` | **1-й аргумент и результат** | читается на входе в 724 функциях из 1188; после возврата читается 1536 раз |
| `%r41..%r45` | **аргументы 2–6** | на входе: r41 436, r42 230, r43 93; вызывающие на них после вызова не полагаются (≤5) |
| `%r34..%r39`, `%r46`, `%r48..%r57`, `%r58..%r61` | **временные** (caller-saved) | после вызова почти не читаются; у `r34..r36` ~50 исключений — вызовы ручных ассемблерных помощников со своим соглашением |
| `%r47` | указатель стека | |
| `%r62` `%sink`, `%r63` `%zero` | приёмник-«чёрная дыра» и ноль | |

Внимание: `%link` и `%from` — это **спецрегистры** s58/s59 (банк 0), а не GPR r58/r59.
GPR r58/r59 — обычные временные (в статье они перепутаны).

## Вызов и возврат

    вызывающий:   %r40..%r45 = аргументы        ; можно в той же молекуле, что и call
                  call f                        ; BRU kind 100, cc[0]=1: %link = адрес возврата
                  ... результат в %r40 ...

    нелистовая функция:
      пролог:     %r47 -= N                     ; N кратно 16 (16..128)
                  %rS = mfsr %link              ; адрес возврата в сохраняемый регистр
                  st [кадр], %r25 / %r26 / …    ; сохранить используемые callee-saved
      эпилог:     ld %r25 / %r26 / … из кадра
                  mtsr %link, %rS               ; (= br.prep статьи)
                  br.ind #hint                  ; переход на %link
                  %r47 += N                     ; в той же молекуле, что и br.ind

    листовая функция (551 из 1188): кадра нет, %link не трогает, возврат сразу br.ind.

Пример — `f_a6798` (обработчик CPUID): кадр 32 байта, `%link` → `%r27`, сохраняются
`%r25..%r27`, возврат `mtsr %link, %r27` + `br.ind #0x76`.

Распределение кадров: без кадра 656, 16 Б — 198, 32 Б — 180, 48 Б — 82, 64/80 Б — по ~25,
до 128 Б. Регистр для копии `%link`: чаще всего `%r25`, `%r26`, `%r27`, `%r11`, `%r15`.

Поле «подсказки» у `br.ind` (`0x74..0x7e`, `0xe0`, `0x164` …) не влияет на цель (она всегда в
`%link`); назначение не выяснено.

## Ограничения ISA, важные для генератора кода

- **У LSU нет адресации «база + смещение»**: адрес всегда в регистре. Каждое обращение к кадру
  или полю структуры требует `addi` в ALU, отсюда цепочки `%r38 = %sp - 12; %r35 = %r38 + 4`.
  Исключение — `ldi rd, base, imm8` (`0x053`) для небольших массивов слов.
- 32-битная константа — только через IMM-слово и только для ALU0 (`addil`, `oril`, `andil`,
  `subil.c` …); в одной молекуле — одна константа.
- Сдвиги — только в ALU1.
- Флаги нельзя выработать и использовать для перехода в одной и той же молекуле (статья);
  в коде CMS сравнение стоит в молекуле перед переходом.
- Атомы молекулы выполняются параллельно: можно менять регистры местами
  (`link = r27; r27 = load(...)`) без временного регистра.
- Цели переходов выровнены на 8 байт, адрес абсолютный (до 64 МБ).
- Аргументы можно вычислять в самой молекуле с `call` — они читаются до перехода.

## Как этим пользоваться

Свою функцию на нашем ассемблере, совместимую с CMS, пишут так: аргументы в `%r40..%r45`,
результат в `%r40`, портить можно только временные регистры, `%r11..%r19`/`%r25..%r33`
сохранять, `%r0..%r10` и `%r20..%r24` не трогать (если не меняем x86-состояние намеренно),
возврат — `mtsr %link` / `br.ind`. Это же соглашение должен реализовать бэкенд компилятора C.
