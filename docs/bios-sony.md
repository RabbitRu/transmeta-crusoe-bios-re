# BIOS Sony Vaio: что внутри R0213P1 и R0248E0

Образы: `RB_R0213P1.EXE` (WinZip SFX, BIOS R0213P1, платформа `SONY IRX-1465`, 2001) и
`R0248E0_UF.EXE` (zip с образом дискеты, BIOS R0248E0, платформа `SONY IRX-1605`, 2004).
`BIOS.ROM` = 581 632 байта = 512 КБ флеша (мапится на 0xFFF80000) + 56 КБ кода для PHLASH.
`R0248E0_WP.EXE` — тот же R0248E0 в обфусцированном Sony-SFX, не распакован.
К каким именно моделям относятся R0213P1/R0248E0 — из файлов не видно.

## Формат модуля PhoenixBIOS 4.0 R6 (реализовано в tools/phxmods.py, unpack.py)

    +0  u32  указатель на предыдущий модуль (0xFFF80000 + смещение)
    +4  00 '1' '1'
    +7  u8 номер, +8 char тип (B,U,M,R,X,A,T,E,S,D,G), +9 u8 длина заголовка (0x1B)
    +10 u8 сжатие (0=нет, 5=LZINT), +11 u16 off, u16 seg, u32 распак.размер, u32 фрагмент, u32 pack/указатель

LZINT (тип 5) = битовый поток LHA `-lh5-` (окно 8 КБ) с префиксом u32 распакованного размера.
Фрагментированный модуль B0: последнее поле — указатель на продолжение с 9-байтным заголовком.

## Частоты/напряжения: BIOS их не задаёт

- Таблицы множителей/напряжений в BIOS нет (ни в R0213, ни в R0248).
- POST-замер (R0248 модуль `B1`+0x3467, R0213 `B2`+0x233B): BIOS пишет в MSR `0x80868010`
  (LongRun) 0/0, затем 100/100 (проценты нижней/верхней границы окна), после каждой записи
  читает CPUID `0x80860007` и кладёт в CMOS — это «CPU Speed» в Setup. Потом восстанавливает.
- Таблица уровней LongRun (R0248, `B1`+0xA5CA): число уровней = EDX из MSR `0x80868018` +1;
  для каждого — запись индекса в `0x80868018`, чтение `0x8086801A`, сборка ACPI (0x1B Б/уровень).
  Сама таблица — внутри CMS.
- Блок конфигурации CMS (R0248, `B2`+0xA1B5): BIOS выделяет буфер, `wrmsr 0x80868000`
  EAX=физадрес буфера EDX=0x80868003, читает dword по +0x428 → «OCT Version» в Setup,
  ветвится по 0x206/0x207.

Строки: «CMS Revision», «CMS Build Path», «Transmeta(tm) Crusoe(tm) Processor», в R0248 ещё
«OCT Version» и «Transmeta PDB-ALI BIOS Label 2000-27, Version 105#1». R0213 содержит
«CPU Soft Update error … perform the CPU Soft Update again» и «CPU Safe Mode» — CMS
обновляется отдельной процедурой, не PHLASH.

Вывод для разгона: править таблицу LongRun внутри CMS, а не BIOS.
